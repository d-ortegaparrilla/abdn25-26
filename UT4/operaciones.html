    Operaciones con registros en DynamoDB

    DynamoDB utiliza una interfaz de programación de aplicaciones (API) para controlar cómo se accede a ella. En RDS se puede utilizar la API de AWS para crear y trabajar con BD. En DynamoDB también se puede utilizar la API para ejecutar consultas y crear y modificar datos dentro de una tabla.

    DynamoDB tiene siete métodos API principales para la manipulación y recuperación de datos:

    • PutItem
    • GetItem
    • UpdateItem
    • DeleteItem
    • ExecuteStatement
    • Query
    • Scan

    PutItem

    Permite cargar registros en la base de datos. Ejemplo:

    aws dynamodb put-item \
    --table-name GameScores \
    --item '{
    "PlayerID": {"S": "KateG"}
    }' \

    La primera línea le indica a DynamoDB qué acción realizará: put-item. La siguiente línea identifica la tabla en la que escribirá y, luego, las líneas finales contienen la información del registro en sí. En este ejemplo, solo escribimos el atributo PlayerID, pero se puede agregar varios atributos si se desea. La sintaxis sigue los estándares JSON, que son comunes en todas las API de AWS.

    GetItem

    Permite devolver un solo registro en función de su clave. Ejemplo:

    aws dynamodb get-item \
    --table-name GameScores \
    --projection-expression "Score, PlayerID" \
    --key '{
    "PlayerID": {"S": "KateG"}
    }' \

    La primera línea le indica a DynamoDB qué acción realizará: get-item. La siguiente línea identifica la tabla de la que leerá. Las líneas finales contienen los detalles clave del registro que se desea devolver. Hay una línea adicional en comparación con el código de PutItem, --projection-expression "Score, PlayerID". Esta línea permite filtrar los atributos que se devuelven y, en nuestro ejemplo, solo se devolverían PlayerID y Score.

    UpdateItem

    Permite modificar un solo registro en función de su clave. Hay cuatro opciones que se pueden utilizar:

    • SET: establece el valor de un atributo de un registro. No es necesario que el atributo exista en la tabla antes de agregarlo, ya que DynamoDB está diseñado para datos no estructurados. Los atributos solo se crean cuando se agregan nuevos registros con nuevos atributos. No los agrega manualmente.
    • REMOVE: elimina el valor de un atributo de un registro.
    • ADD: agrega un valor a un conjunto (nos referimos a los tipos de DynamoDB conjunto de cadenas, conjunto de números o conjunto binario), que es un atributo especial similar a una matriz.
    • DELETE: elimina un valor de un conjunto.

    Cada una de estas opciones requiere de una sintaxis diferente.

    SET

    aws dynamodb update-item \
    --table-name GameScores \
    --key '{
    "PlayerID": {"S": "KateG"}
    }' \
    --update-expression 'SET Score = :s' \
    --expression-attribute-values '{
    ":s": {"N": "4523"}
    }' \

    La primera línea le indica a DynamoDB qué acción realizará: update-item. La siguiente línea identifica la tabla en la que escribirá y, luego, la tercera línea contiene los detalles clave del registro en sí que desea actualizar. Las siguientes líneas le indican a DynamoDB qué atributo actualizar. La línea --update-expression 'SET Score = :s' le indica a DynamoDB qué hacer con ese registro, en este caso 'SET Score = :s'. :s es una variable que pasamos en la siguiente línea, --expression-attribute-values '{":s": {"N": "4523"}'.

    REMOVE

    aws dynamodb update-item \
    --table-name GameScores \
    --key '{
    "PlayerID": {"S": "KateG"}
    }' \
    --update-expression "REMOVE Score"\
    }' \

    La primera línea le indica a DynamoDB qué acción realizará: update-item. La siguiente línea identifica la tabla en la que escribirá y, luego, la tercera línea contiene los detalles clave del registro que desea actualizar. Las siguientes líneas le indican a DynamoDB qué atributo eliminar. La línea --update-expression "REMOVE Score" le indica a DynamoDB que elimine el valor almacenado en el atributo.

    DELETE y ADD

    Estas dos opciones sirven para trabajar con conjuntos y permiten eliminar y agregar valores a un conjunto existente. Un conjunto es un array de valores del mismo tipo.

    DeleteItem

    Permite eliminar un solo registro en función de su clave. La sintaxis difiere de la función delete utilizada en la API UpdateItem, ya que elimina un valor de un conjunto, pero la API DeleteItem elimina un registro completo:

    aws dynamodb delete-item \
    --table-name GameScores \
    --key '{
    "PlayerID": {"S": "KateG"}
    }' \
    --condition-expression "Score < :a" \
    --expression-attribute-values '{
    ":a": {"N": "5000"}
    }' \

    La primera línea le indica a DynamoDB qué acción realizará: delete-item. La siguiente línea identifica la tabla en la que escribirá y, luego, las líneas finales contienen los detalles clave del registro en sí que desea devolver. Hay una línea adicional: --condition-expression "Score < :a". Esta línea le permite eliminar el registro solo si existen ciertas condiciones; en este caso, solo elimine KateG si su puntaje es menor a 5000.

    ExecuteStatement

    Permite ejecutar consultas en la tabla DynamoDB utilizando la sintaxis de consulta PartiQL. La sintaxis de consulta PartiQL sigue la sintaxis SQL estándar, lo que permite utilizar instrucciones de tipo SELECT, INSERT, UPDATE y DELETE.

    Query

    Ya vimos anteriormente cómo consultar una tabla de DynamoDB. Ahora veremos el código que usaría para hacerlo y qué se puede y no se puede consultar. Una consulta es extremadamente rápida, incluso en una tabla con millones de filas, ya que se puede ir directamente a la fila requerida. No hay que olvidar que una GSI agrega valores de clave adicionales, por lo que, si se tiene un atributo que se necesita consultar que no está incluido en las claves de la tabla base, agregar una GSI puede ayudar a mejorar el rendimiento.

    Una consulta en una tabla de DynamoDB solo se puede realizar en la clave de partición, por lo que en nuestra tabla GameScores, solo podemos usar las columnas PlayerID y GameName para una consulta para filtrar. Un ejemplo de consulta para obtener los puntajes de un jugador determinado que jugó un juego determinado es el siguiente:

    aws dynamodb query \
    --table-name GameScores \
    --key-condition-expression "PlayerID = :playerid AND 
GameName = :gamename"\
    --expression-attribute-values '{
        ":playerid": { "S": "KateG" },
        ":gamename": { "S": "Space Mission" }
    }'
    --projection-expression "PlayerID, GameName"

    La línea --projection-expression "PlayerID, GameName" controla qué atributos se devuelven al usuario o a la aplicación y puede resultar útil para acelerar las consultas si se tienen una gran cantidad de atributos. Esta línea se puede utilizar en todos los demás comandos de tipo de recuperación utilizados en DynamoDB, como get-item y scan.

    Scan

    Un escaneo se utiliza cuando se necesita filtrar por un atributo que no está incluido en ninguna clave de tabla o de índice. Puede ser útil si no se necesita filtrar regularmente por este atributo y, por lo tanto, un GSI o LSI puede no ser una decisión de diseño sensata.

    Para ejecutar un escaneo, se puede utilizar una sintaxis similar a la siguiente para obtener todos los registros donde la puntuación más alta sea mayor que 5000:

    aws dynamodb scan \
    --table-name GameScores \
    --filter-expression "Score > :score" \
    --expression-attribute-values '{":score":{"S":"5000"}}'

    Un escaneo leerá cada registro de la tabla, y esto puede rápidamente volverse muy costoso. En general, se deben evitar los escaneos a menos que se trate de un caso de uso único que no se pueda responder mediante una consulta.
