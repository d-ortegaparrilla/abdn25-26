    Introducción

    Amazon DynamoDB es un servicio de base de datos NoSQL y sin servidor totalmente administrado que admite estructuras de datos de documentos y de clave-valor. Es un motor de base de datos propietario que solo ofrece AWS. Una base de datos NoSQL es una base de datos diseñada para almacenar datos semiestructurados o no estructurados sin un esquema concreto. DynamoDB es una base de datos de clave-valor, lo que significa que todos los datos se almacenan con una clave que actúa como un identificador para los datos y los valores, que son los atributos. Una base de datos sin servidor es una para la que no se necesita definir los requisitos de cómputo. Cuando se aprovisiona una instancia de RDS, se necesita calcular la cantidad de CPU y la cantidad de memoria que necesitará. Cuando se aprovisiona DynamoDB, no se necesita hacerlo y se puede optar por ejecutar en modo on-demand, donde AWS administrará la capacidad de su tabla DynamoDB usa la cantidad de datos que lee y escribe la aplicación para calcular los cargos en lugar de los requisitos de cómputo.

    Tipos de datos

    Una tabla de DynamoDB puede almacenar datos en los siguientes formatos:

    • String: un valor que puede contener letras y números:

      "Name": { "S": "Kate" }

    • Number: un valor que solo puede contener números, incluyendo un punto decimal:

      "Score": { "N": "1045" } - Binary: un valor que puede almacenar tipo de datos complejos en formato base64. Puede almacenar imágenes y documentos:

      "Image": { "B": "bXkgc3VwZXIgc64jcmV0IHRlehrsh" } - Boolean: un valor que solo puede almacenar true o false:

      "Parent": { "BOOL": "false" } - Null: un valor que puede ser true o false:

      "Empty": { "NULL": "true" } - List: un array de valores del mismo o diferentes tipos de datos, como strings o numbers:

      "Objects": { "L": [ "Book", "98" ] } - Map: una colección de parejas clave-valor permitiendo datos anidados:

      "ChildrenDetails": { "M": { "Dave": { "Relationship": "Son", "Age": 12 }, "Amy": { "Relationship": "Daughter", "Age": 9, "HairColour": "Brown" } } - String set: una lista de strings:

      "Children": { "SS": [ "Dave", "Amy" ] }

    • Number set: una lista de números:

      "Codes": { "NS": [ "16436", "98464" ] }

    • Binary set: una lista de valores binarios:

      "Images": { "BS": [ "aGVbG93b3JsZA==", "c2VjcmV0cw==" ] }

    Si bien DynamoDB puede tener un esquema indefinido, lo que significa que se pueden crear nuevos atributos en tiempo de ejecución que difieran para cada registro de la tabla, hay que asegurarse de que los tipos de atributos sean consistentes. Por ejemplo, no se puede insertar una cadena en un atributo numérico.

    Para usar DynamoDB, se debe tener en cuenta lo siguiente:

    • ¿Qué clave quiero usar para mi tabla?
    • ¿Cuántos datos leeré y escribiré en mi tabla?
    • ¿Cuánto almacenamiento necesitaré?
    • ¿Debo considerar opciones de alta disponibilidad o recuperación ante desastres?

    DynamoDB es una base de datos sin servidor, por lo que no se implementa dentro de una VPC. Para poder tomar una decisión sobre estas cuatro preguntas, primero veamos cómo se diseña una tabla de DynamoDB.
